# Permission States — правду выясняет перезапуск, а не догадка

Версия 6. Схема пользователя: **не пытаемся определить «нужен ли перезапуск».**
Пользователь выдаёт право → нажимает «Run macVNC» → приложение перезапускается →
при старте проверяется, выдано ли реально.

## Наблюдавшиеся баги (обязаны исчезнуть)

1. чип «↻ Restart required» + текст «All permissions granted» одновременно;
2. статус «Granted» при фактически сброшенном праве;
3. в System Settings нет строки macVNC — включать нечего;
4. цикл: дал права → «нужен перезапуск» → перезапуск → снова то же.

## Измерения на этой машине (2026-08-25)

| Приём | Диалог | Создаёт строку | Проверено |
|-------|--------|----------------|-----------|
| `CGPreflightScreenCaptureAccess()` | нет | нет | да |
| `getShareableContent` при отказе | нет | нет (`-3801` сразу) | да |
| `CGRequestScreenCaptureAccess()` | **ДА** | да | — |
| `AXIsProcessTrustedWithOptions(prompt=NO)` | **нет** | **ДА** | да, строка появилась |
| AppleScript управления Настройками | **ДА** (AppleEvents TCC) | — | да, отдельная служба |

### Почему нельзя опрашивать preflight

| Состояние | Захват в процессе | `CGPreflight` |
|-----------|-------------------|---------------|
| право сброшено | не было | NO |
| право ВЫДАНО | не было | NO |
| право ВЫДАНО | **захват идёт, 1109 кадров** | **NO** |

`CGPreflight` возвращает NO **всегда** — даже когда захват реально работает.
Сигнал бесполезен полностью. Отсюда все прошлые зацикливания.

### Критично: способ запуска определяет права

| Запуск | Право выдано | Результат захвата |
|--------|--------------|-------------------|
| из терминала | да | **`-3801`, 0 кадров** |
| через `open` (GUI) | да | **0 отказов, 1109 кадров** |

macOS атрибутирует захват тому, кто запустил процесс. Поэтому перезапуск обязан
идти через `/usr/bin/open` — в `relaunchApplication` это уже так.

Следствие для тестирования: **запуск бинарника из shell всегда даёт `-3801`**,
и это не баг приложения. Проверять только GUI-запуском.

## Единственный надёжный сигнал — реальный захват

```
захват работает      → право есть
захват упал -3801    → права нет (при GUI-запуске)
AXIsProcessTrusted() → надёжен, обновляется без перезапуска
```

«Выдано, но нужен перезапуск» **не определяется** ни одним доступным сигналом:
измерения для «не выдано» и «выдано, но не применено» совпадают. Поэтому это
состояние **не показывается** — вместо него работает схема с перезапуском.

## Схема: выдал → Run macVNC → перезапуск → проверка

```
1. Панель: право не работает → «Откройте Настройки»
   (+ подсказка про «+», если macVNC нет в списке)
2. Пользователь включает право в Настройках
3. Возвращается, жмёт «Run macVNC»
4. Приложение ПЕРЕЗАПУСКАЕТСЯ через /usr/bin/open
5. Новый процесс пробует захват:
      получилось → сервер работает, панели нет
      отказ      → панель снова: «Права всё ещё нет»
```

Никаких догадок: правду выясняет сам перезапуск. Цикл невозможен, потому что
после перезапуска состояние определяется **фактом**, а не признаком.

## Состояния чипа

| Чип | Когда |
|-----|-------|
| ⚠ Не выдано | захват отказан (или ещё не пробовали) |
| ✓ Выдано | захват работает / `AXIsProcessTrusted()` |

Два состояния на право — потому что третье неотличимо. Это честно: мы не
утверждаем того, что не можем измерить.

## Матрица

| # | SR | AX | Кнопка | Текст |
|---|----|----|--------|-------|
| S0 | — | — | панели нет | сервер работает |
| S1 | ⚠ | ⚠ | **Run macVNC** | Включите оба права в Настройках, затем нажмите Run macVNC. Если macVNC нет в списке — «+» → Программы. |
| S2 | ⚠ | ✓ | **Run macVNC** | Включите Screen Recording, затем нажмите Run macVNC. Если macVNC нет в списке — «+» → Программы. |
| S3 | ✓ | ⚠ | **Run macVNC** | Включите Accessibility, затем нажмите Run macVNC. |
| S4 | ✓ | ✓ | **Run macVNC** | Всё выдано. |

Кнопка везде одна — **«Run macVNC»**, и она всегда активна (нет disabled-тупиков).
Её действие: если права уже работают — просто старт; если нет — перезапуск с
проверкой. Пользователю не нужно понимать разницу.

Отдельная кнопка «Открыть настройки» — клик по самому чипу.

## Инварианты

- **I1** текст и чипы — из одного снимка сигналов на рендер (сейчас три
  независимых замера за рендер — причина бага №1);
- **I2** никогда не показываем «нужен перезапуск» как измеренный факт;
- **I3** системный диалог не поднимаем; AppleScript управления Настройками тоже
  запрещён (диалог AppleEvents);
- **I4** сервер работает → панели нет;
- **I5** кнопка всегда активна;
- **I6** показанный статус = результат реального захвата или системного API;
- **I7** перезапуск только через `/usr/bin/open` (иначе TCC атрибутирует чужому
  процессу и захват отказывает).

## Не делаем

- `CGRequestScreenCaptureAccess` (диалог).
- AppleScript управления Настройками (откачено).
- Правки TCC.db (SIP не применяет).
- Опрос preflight как источник истины — доказано бесполезен.
- Безусловный `tccutil reset` (стирает чужие гранты).
