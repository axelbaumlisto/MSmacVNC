## Осталось

### 1. Убрать замерный лог и мёртвый код

- временный `PREFLIGHT_AT_LAUNCH` из `applicationDidFinishLaunching`;
- `macVNCEnsureListedInScreenRecordingSettings` — доказано, что строку не создаёт;
- `macVNCRequestPermissionPrompt` / `macVNCRequestPermissionAndOpenSettings` —
  поднимают системный диалог, вызовов нет (I3);
- `macVNCPermissionsAllowStartAttempt` — уходит вместе с новой моделью.

### 2. Честные сигналы + чистый резолвер

```c
typedef struct {
    BOOL axTrusted;        /* AXIsProcessTrusted() — надёжен          */
    BOOL captureWorking;   /* захват реально идёт                     */
    BOOL captureDenied;    /* -3801 в этом запуске                    */
    BOOL serverRunning;    /* vncServerGetPort() > 0                  */
} MacVNCPermissionSignals;

MacVNCPermissionSignals macVNCCaptureSignals(void);   /* единственный замер */
MacVNCPermissionUIState macVNCResolvePermissionUI(MacVNCPermissionSignals);
```

`CGPreflight` **не входит** в сигналы: замерено, что он даёт NO даже при
работающем захвате.

`UIState` несёт: чип SR, чип AX, текст, `shouldShowPanel`. Кнопка всегда
«Run macVNC» и всегда активна (I5). Панель ничего не решает — только рисует.

Причина бага №1 устраняется здесь: сейчас за один рендер делается три
независимых замера TCC, поэтому чип и текст расходятся (I1).

### 3. Кнопка «Run macVNC»

Одно действие на все состояния:

```
если права уже работают → просто старт сервера
иначе                    → перезапуск через relaunchApplication
```

Перезапустившийся процесс пробует захват; результат и есть проверка. Никаких
признаков «нужен перезапуск» (I2).

Защита от бесконечного перезапуска: если процесс запущен перезапуском и захват
снова отказан, панель показывает «Права всё ещё нет» и кнопка снова доступна —
но перезапуск инициирует **только пользователь**, автоматически никогда.

### 4. Когда панель не показывается

- **M1** `serverRunning` → никогда;
- **M2** при старте: захват удался → сервер работает **молча**, формы нет;
- **M3** панель уже открыта → не плодить вторую;
- **M4** несколько отказов подряд → один модал, не стопка.

Отзыв права во время работы: сначала стоп сервера (уже вне главного потока),
потом панель.

### 5. Никакого автостарта по таймеру

Панель обновляет сигналы раз в секунду, но сервер поднимается только по клику:
`runModal` блокирует главный поток, и **сетевой слушатель VNC не должен
подниматься без явного действия пользователя** (аргумент sec-критика).

## Тесты (чистые, без AppKit)

```
S0 serverRunning            → shouldShowPanel == NO
S1 SR⚠ AX⚠                  → оба чипа ⚠, текст содержит "+"
S2 SR⚠ AX✓                  → чип AX ✓, текст содержит "+"
S3 SR✓ AX⚠                  → текст про Accessibility
S4 SR✓ AX✓                  → "Всё выдано"
I1 текст и чипы согласованы во всех состояниях
I2 ни в одном состоянии нет "нужен перезапуск"
I5 кнопка активна везде
M2 захват работает + AX✓ на старте → панель не показывается
```

## Живая проверка (осторожно)

- **только GUI-запуск** (`open /Applications/macVNC.app`). Запуск бинарника из
  shell всегда даёт `-3801` — замерено, это не баг приложения;
- **адресный сброс**: `tccutil reset ScreenCapture net.christianbeier.macVNC`
  (без bundle id стирает гранты всех приложений);
- **бэкап**: `cp -R /Applications/macVNC.app /tmp/rb-<ver>.app`;
- **установка `ditto` поверх**, никогда `rm -rf` — удаление бандла губит запись
  TCC (подпись тут не виновата: TCC привязывает грант к bundle id + Team ID,
  урок clipshot `tcc_reset.rs`);
- сценарий: сброс SR → GUI-запуск → S2 с подсказкой «+» → включил право →
  «Run macVNC» → перезапуск → **AUTH_OK через `/tmp/refclient`** (не vncdotool:
  даёт ложный AUTH_OK) → кадры, оба монитора;
- **откат наготове**: `/tmp/rb-prev.app`, `/tmp/rb-322.app`.

## Порядок работ

1. чистка мёртвого кода и замерного лога;
2. сигналы + резолвер + тесты — до интеграции;
3. панель как тонкий рендер, единая кнопка «Run macVNC»;
4. AppDelegate: показ панели по `shouldShowPanel`, молчаливый старт при M2;
5. сборка, `ditto` поверх, живая проверка GUI-запуском.

## Принятый риск

Screen Recording пользователь один раз добавляет через «+»: тихой регистрации
для этого права в macOS нет (проверено), а `CGRequestScreenCaptureAccess`
показывает системное окно и запрещён.
